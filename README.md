# Wanderly Travel Agent

旅行助手智能体的前端原型。

直接在浏览器中打开 `index.html` 可查看视觉原型：欢迎页使用 `Photos/` 下的旅行图片，并每 3 秒自动切换；右上角按钮可手动切图。AI 识别、保存、相册等真实功能需要先运行 `npm start`，再访问 `http://localhost:3000`。若直接打开文件，前端也会尝试连接该地址，并在服务未启动时给出明确提示。

## 数据模型

旅行对象、AI 输出格式与局部重规划约定见 [docs/mvp-data-model.md](docs/mvp-data-model.md)。共享 TypeScript 类型位于 `src/types/trip.ts`，JSON Schema 位于 `schemas/trip.schema.json`。

## 本地服务与数据库

项目使用 Node.js 内置 HTTP 与 SQLite 能力，无需安装依赖。运行 `npm start` 后，在 `http://localhost:3000` 打开网页；API 与 SQLite 数据库会一同启动。接口说明见 [docs/api.md](docs/api.md)。

服务默认只监听 `127.0.0.1`，且只对外提供首页与 `Photos/` 图片；`.env.local`、源代码和 SQLite 数据不会被静态下载。需要容器或局域网访问时，使用 `TRAVEL_AGENT_HOST` 显式配置监听地址，并在正式部署前增加 HTTPS 与身份认证。

## AI 行程生成

将 `.env.example` 复制为 `.env`，设置 `DEEPSEEK_API_KEY` 后，服务端会使用 DeepSeek Responses API 先识别自然语言中的人数、天数、预算、目的地、模糊时间与偏好，再生成结构化行程。确认页支持直接编辑或继续补充需求；目的地、天数和人数补齐前不会创建数据库草稿。密钥只在服务端环境变量中使用；具体接口与输出规则见 [docs/api.md](docs/api.md)。

AI 请求带有可配置超时，所有行程写操作使用版本号防止旧页面覆盖较新的保存结果；发生冲突时客户端会重新加载最新行程。

生成后的行程支持调整整段或指定日期，并可锁定某一天或某个活动。服务端会强制保护锁定内容，同时保存每次 AI 修改的摘要、预算变化和版本记录；行程页的“修改记录”可以随时回看这些信息。

“我的行程”页面会读取 SQLite 中的旅行记录，支持按状态筛选、继续草稿、打开已生成行程以及归档和恢复旅行。

“旅行相册”可以选择任意未归档旅行，上传 JPEG、PNG 或 WebP 并关联到某一天。照片文件保存在 `data/uploads/`，元数据随旅行写入 SQLite；本地图片目录默认不会提交到 Git。

“行前清单”可以按目的地、时间、同行人和已有行程让 DeepSeek 生成个性化准备事项，也支持手动添加、分类、勾选和删除。完成状态会保存在 SQLite，重新生成时不会丢失已完成与手动事项。

行程详情会展示人均总预算和大交通、住宿、餐饮、景点活动、预留金分类，并根据用户输入的预算自动提示预算是否充足、接近上限或可能超支。

行程生成和重规划会同步产出结构化住宿区域与交通建议，包括适合人群、建议晚数、住宿预算区间和分段移动方式；页面明确标注这些内容不代表实时库存、班次或报价。

生成后的行程可以创建带随机令牌的只读分享链接，也可以导出为包含旅行概览、预算、逐日活动、提示与行前清单的 Markdown 文件。分享接口会过滤原始对话、个人限制、相册和清单；链接仍需能够访问同一服务实例。
